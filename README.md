# MyWork

개인 업무 관리 대시보드. WorkDesk 프로토타입 디자인을 그대로 옮기고, 데이터를 로컬 SQLite에 영구 저장한다.

## 스택

| 영역 | 선택 | 이유 |
|------|------|------|
| 서버 | Express 5 | REST 라우팅만 필요 |
| DB | `node:sqlite` (Node 22 내장) | better-sqlite3 등 네이티브 드라이버 불필요 |
| 프론트 | 바닐라 JS + 정적 파일 | 빌드 단계 없음. `public/`을 그대로 서빙 |

의존성은 `express`, `@modelcontextprotocol/sdk`(MCP), `@anthropic-ai/sdk`(AI 지시창).

## 실행

```bash
npm install && npm start
```

http://localhost:4000 (포트는 `PORT` 환경변수로 변경)

```bash
npm test
```

## 뷰

- **요약** — 큰 «오늘» 제목 + 한 문장 현황(`10월 12일 월요일 · 지연 3 · 미완료 12`). 지연 → 오늘 마감 → 이번 주 → 대기 순의 흰 판 그룹. «언젠가»와 «분류별 현황»은 접혀 있고 펼침 상태가 유지된다. 지연 그룹 머리의 «모두 미루기 ▾»로 지연 전체의 마감을 오늘·금요일·지정일로 옮긴다
- **목록** — 묶음 리스트. `상태별 / 분류별 / 마감순` 탭(선택 유지). 그룹 안은 마감일 순, 완료 건은 항상 뒤. 하위는 상위 아래 들여쓰기, 상위가 다른 그룹이면 메모 줄에 `↳ 상위 제목`
- **보드** — 진행상황 칸반. 열은 272px 고정폭(넘치면 가로 스크롤). 카드는 제목 + 한 줄 메타(분류 · 체크리스트 · 하위 · 반복 · 마감 «N일 지연»). 카드를 끌면 상태 변경, **열 머리를 끌면 열 순서 변경**(= 진행상황 설정 순서)
- **캘린더** — 마감일 기준 월간 뷰
- **메모** — Keep 스타일 메모 보드. 빠른 작성, 고정·색상·보관, 태스크 연결/전환

**프로젝트 뷰**(`/project`)는 메뉴에 없다 — 아래 «프로젝트 뷰» 참고.

### 빠른 입력

`n` 또는 헤더의 `＋ 새 태스크`를 누르면 화면 위쪽에 한 줄 입력 바가 뜬다. `금요일까지 #인사시스템 발령 에러 확인`처럼 치고 `Enter`를 누르면 마감·분류가 채워진 태스크가 즉시 생기고, 바는 비워진 채 남아 연속으로 넣을 수 있다. 입력하는 동안 바 아래 칩이 «이렇게 들어간다»를 보여 준다.

| 표현 | 해석 |
|---|---|
| `오늘` `내일` `모레` | 그날 |
| `금` `금요일` · `이번주 금` · `다음주 월요일` | 다가오는 그 요일(오늘이면 오늘) · 이번 주 · 다음 주 |
| `10/20` `10.20` `10월 20일` · `20일` | 그 날짜(지났으면 다음 해) · 이번 달(지났으면 다음 달) |
| `…까지` | 날짜 뒤에 붙으면 함께 지운다 |
| `#분류` | 분류 지정(제목에서 지움). 분류 이름이 문장에 그대로 있으면 그 분류로 잡되 제목에 남긴다 |

- 해석은 로컬 규칙(`public/quickparse.js`)이다 — Enter마다 AI를 기다리지 않는다. 긴 문장·여러 건은 AI 지시창(`i`)으로.
- 분류를 못 찾으면 사이드바 분류 필터, 그것도 없으면 첫 분류(칩이 흐리게 보인다). 상태는 첫 미완료 상태.
- `Shift+Enter`는 해석 결과를 채운 전체 모달을 연다. `Esc`·바깥 클릭은 저장하고 닫는다(비어 있으면 그냥 닫힘).
- 저장 직후 토스트 «… 추가됨»의 `수정`은 편집 모달을, `되돌리기`는 방금 만든 태스크를 지운다.

공통: 검색(제목·메모·체크리스트), 분류 필터, 사이드바 분류 토글. 헤더의 완료 숨김·정리·설정·AI 지시는 아이콘 버튼이다(라벨은 툴팁).

요약·목록 행 앞의 **동그라미는 완료**다. 누르면 즉시 취소선이 그어지고 토스트 «완료 · 되돌리기»가 뜬 뒤 **5초 후 확정**된다(삭제 되돌리기와 같은 장치). 반복 태스크는 완료 PATCH 때 서버가 다음 회차를 만들기 때문에, 확정 전 되돌리기라야 다음 회차가 남지 않는다. 완료 행의 동그라미를 누르면 바로 미완료로 돌아간다.

디자인은 부드러운 Things풍 — 회색 앱 배경(`#F4F4F6` / 다크 `#0F1115`) 위에 흰 둥근 판(반경 12px, 옅은 그림자 / 다크는 1px 테두리), 알약 모양 버튼·칩, 인디고 액센트 1색(`#5E6AD2` / `#8B93F5`). 설계 근거는 `docs/superpowers/specs/2026-10-12-soft-ui-design.md`.

단축키: `/` 검색 포커스, `n` 빠른 입력, 모달에서 `Ctrl+Enter` 저장. 입력 중이거나 모달이 열려 있으면 `/`·`n`은 무시된다.

좁은 화면(`≤1100px` 뷰 제목 숨김, `≤960px` 세로 스택, `≤560px` 폰 압축)에 대응한다. 960px은 헤더 컨트롤 최소 폭 686px + 사이드바 232px에서 나온 값이라 iPad 세로(768px)도 포함한다. 폰에서는 사이드바가 상단 가로 바가 되고(분류 토글은 헤더 select가 대신), 페이지 전체가 스크롤한다. **보드·프로젝트 뷰는 가로 스크롤**에 맡긴다 — 열이 좁아지면 읽을 수 없다. 요약·목록은 세로로 읽힌다(폰에서는 분류 알약을 숨긴다).

보드 열 머리 오른쪽의 `+`는 **인라인 빠른 추가**다(입력창은 열 맨 위에 뜬다). 제목만 치고 Enter를 누르면 그 열의 상태 + 현재 필터의 분류로(마감 없음) 바로 생성되고, 입력창이 비워져 연속으로 추가할 수 있다. 닫는 모든 경로(Esc·바깥 클릭)가 저장이다 — 메모 빠른 작성과 같은 규칙이며, 비어 있으면 그냥 닫힌다. 나머지 필드를 채우려면 빠른 입력 바(`n`·`＋ 새 태스크`)에서 `Shift+Enter`로 전체 모달을 열거나 만든 뒤 카드를 눌러 수정한다.

## AI 지시창

헤더의 `AI 지시`(단축키 `i`)로 자연어 지시를 내리면 Claude가 태스크·메모를 직접 조회·수정한다.
도구는 MCP 서버와 **같은 `tools.js`**라서 Claude Code로 지시할 때와 규칙·결과가 같다.

`.env.example`을 `.env`로 복사해 키를 채운다. `.env`는 git 제외이고, 셸 환경변수가 있으면 그쪽이 우선한다(Node 내장 `process.loadEnvFile`, 의존성 없음).

```bash
cp .env.example .env
```

- 모델 `claude-opus-5-5`(effort medium), 거절 시 서버 측 `fallbacks: "default"`로 다른 모델이 이어받는다.
- 서버는 무상태다. 대화 이력은 브라우저 `sessionStorage`에 두고(뷰를 옮겨도 이어짐) 매 요청에 최근 20턴 텍스트만 보낸다.
- 한 지시당 도구 왕복은 최대 12회. 변경이 있었으면 응답 직후 화면 데이터를 다시 불러온다.
- **삭제는 AI가 실행하지 않는다.** 삭제 도구 호출은 말풍선의 확인 목록(삭제/취소, 2건 이상이면 «모두 삭제»)으로 바뀌고, 누르면 프론트가 기존 REST `DELETE`로 직접 지운다. 결과(삭제함/취소함)는 대화 이력에 남아 다음 지시 때 모델이 안다. 보관은 복원 가능하므로 확인 없이 실행한다.
- 응답 말풍선 아래 칩은 실제로 바뀐 것(생성·수정·삭제)만 보여 준다. 조회 도구는 숨긴다.
- 워크스페이스에 묶이지 않은(조직 단위) 키는 `.env`에 `ANTHROPIC_WORKSPACE_ID`도 넣어야 한다 — `anthropic-workspace-id` 헤더로 붙는다.
- 키가 없으면 지시창에 설정 안내가 뜰 뿐 나머지 앱은 그대로 동작한다.

## 삭제 되돌리기

완료 동그라미도 같은 장치를 쓴다.

목록의 `×`와 모달의 `삭제`는 곧바로 서버로 가지 않는다. 태스크를 화면에서 감추고 하단에 토스트를 띄운 뒤 **5초 후에 확정**한다. 그 사이 `되돌리기`를 누르면 아무 일도 일어나지 않는다 — 요청 자체를 보내지 않았으므로 체크리스트 CASCADE도 발생하지 않고, 복원 로직이나 스키마 변경도 필요 없다.

- 대기 중에 다른 태스크를 지우면 앞선 건이 먼저 확정된다. 토스트는 항상 하나다.
- 뷰 전환은 페이지 이동이라 `pagehide`에서 대기 건을 흘려보낸다(`fetch(..., { keepalive: true })`). 그래서 지우자마자 다른 뷰로 넘어가도 삭제는 유실되지 않는다.
- 브라우저가 그 전에 죽으면 요청이 안 나가 태스크가 살아남는다. 지워야 할 게 남는 쪽이 지우지 말아야 할 게 사라지는 쪽보다 안전하다.

보관 모달의 `영구 삭제`는 예외로 확인 창을 그대로 쓴다. 이미 «되돌릴 수 없음»을 전제로 한 동작이기 때문이다.

## 없앤 축 — 우선순위 · 업무유형 · 시작일

이 앱은 프로젝트 관리로 출발했지만 실제 쓰임은 **여러 채널로 흩어져 들어오는 개인 업무를 놓치지 않는 것**이다. 실사용 44건의 분포가 그 미스매치를 드러냈고, 정보를 주지 못하는 축을 걷어냈다.

| 축 | 실제 분포 | 처리 |
|---|---|---|
| 우선순위 | Medium 40 : High 4 : Low 0 | 제거 |
| 업무유형 | 상위 2종(개발·기획·문서)이 86% | 제거 — 업무분류와 역할이 겹쳤다 |
| 시작일 | 대부분 «만든 날» 근처의 자리채움 | 화면에서는 뺐다. 편집·표시는 **프로젝트 뷰**에서만 |

- `tasks`의 `type`·`priority` **컬럼은 남겼다**. `NOT NULL DEFAULT`라 `INSERT`에서 생략해도 채워지고, 되돌릴 수 없는 삭제를 이득 없이 할 이유가 없다. 지운 건 `options` 행뿐이다.
- 남은 축은 **진행상황 · 업무분류 · 마감일** 셋이다. 태스크 모달이 제목·진행상황·분류·마감일·메모로 줄었다.
- 요약·프로젝트 뷰의 색 점은 **업무분류 색**을 쓴다. 사이드바 점과 같은 의미다.
- 정렬은 전부 **마감일 순**이다. 마감 없는 건은 항상 뒤로 간다.

헤더의 **완료 숨김** 토글은 목록·보드·캘린더에만 적용된다. 요약 뷰는 완료 건수를 보여야 하므로 제외한다. 보드의 `완료` 열은 비어 보여도 드롭 대상으로 남아 있어, 숨긴 상태에서도 드래그로 완료 처리할 수 있다.

검색어·분류·`완료 숨김`은 `localStorage`에 저장되어 **뷰를 오가거나 새로고침해도 유지된다**. 뷰가 물리 페이지 분리라 메모리 상태는 매번 초기화되는데, 매일 같은 필터를 다시 거는 마찰이 커서 필터만 살렸다. 설정에서 지워진 값이 남아 있으면 로드 시 `전체`로 되돌아간다.

목록 뷰는 정렬 기준과 무관하게 **완료 행을 항상 하단**에 둔다. 첫 화면이 끝난 일로 시작하지 않게 하기 위해서다.

태스크·메모 모달은 저장하지 않은 변경이 있는 채로 닫으면(Esc·배경 클릭·취소·`×`) **확인 창을 한 번 띄운다**. 체크리스트·하위 태스크는 즉시 저장이라 비교 대상이 아니다. 모달의 상위 태스크 후보에는 완료 태스크가 나오지 않고(이미 연결된 상위는 예외), 제목 뒤에 마감일이 붙어 같은 이름의 반복 회차를 구분할 수 있다.

## 마감일 없음 («언젠가»)

마감일은 **선택**이다(`due`가 `NULL`). 종전에는 필수였고 새 태스크에 자동으로 «7일 뒤»가 붙었는데, 그 탓에 「언젠가 할 일」이 `8/31`·`12/31` 같은 가짜 마감을 달고 **지연 건수를 오염**시키고 있었다. 지연 숫자가 거짓이면 요약 뷰 전체가 무력해진다.

- 새 태스크·보드 빠른 추가·MCP `create_task` 모두 **기본이 마감 없음**이다.
- 모달의 마감일을 비우면 해제된다. `PATCH`에 `due: null`(또는 `""`)을 주는 것과 같다.
- 요약의 «오늘의 액션»과 `today_brief`에 **«언젠가»** 버킷이 생겼다. 지연·오늘·예정 어디에도 들어가지 않는다.
- 목록 정렬에서 마감 없는 건은 항상 뒤로 간다. 캘린더에는 나타나지 않는다.
- **반복 태스크는 마감일이 필수**다. 다음 회차를 «직전 마감 + 주기»로 잡기 때문에 기준이 없으면 계산할 수 없다. 위반하면 400.
- 마감도 완료 시각도 없는 건은 **보관 대상에서 빠진다**. 끝낸 날을 모르는 걸 기준 없이 치우지 않는다.

내부적으로 필드 검증의 «실패» 신호를 `null` → `undefined`로 바꿨다. `due`는 `null`이 정상 값이라, `null`을 실패로 쓰면 «마감 지움»과 «잘못된 날짜»를 구분할 수 없다.

## 대기 중 (공이 남에게 있음)

진행상황에 `waiting` 플래그를 둔다. `done`과 같은 방식으로, **이름이 아니라 플래그**가 기준이다.

- `waiting` 상태의 태스크는 **마감이 지나도 지연으로 세지 않는다**. 내 차례가 아니기 때문이다. 마감일 표시도 붉은 «N일 지연» 대신 회색 «MM/DD 대기»가 된다.
- 요약의 «오늘의 액션»과 `today_brief`에 **«대기 · 남의 차례»** 버킷이 따로 있고, 지연 일괄 재조정 대상에서도 빠진다.
- `done`과 동시에 지정할 수 없다(400). 끝난 일이 «남의 차례»일 수는 없다.
- `done`과 달리 **하나도 없어도 된다**. 기준이 사라져도 잃는 기능이 없다.

기존 DB에는 자동으로 추가되지 않는다. 설정 → 진행상황에서 상태를 만들고 `대기`를 체크하면 된다. 새 DB에는 `대기 중`이 기본으로 들어간다.

실데이터에 `심준 대리 회신`, `ITSM 등록 필요` 같은 «남의 차례» 업무가 이미 있었는데, 그것이 내 할 일과 같은 줄에 서서 지연으로 세이고 있었다.

## 오늘의 액션 (요약 뷰)

MCP의 `today_brief`와 같은 5분류를 요약 뷰 상단에 보여준다: **지연 / 오늘 마감 / 예정(7일 내) / 언젠가(마감 없음) / 대기(남의 차례)**. 7일 밖 마감은 건수로만 표시한다. 비어 있는 섹션은 그리지 않는다.

앞의 세 버킷은 **마감이 있고 내 차례인** 것만 담는다. 대기 건은 마감이 지나도 지연에 들어가지 않고, 마감 없는 건은 «언젠가»로 빠진다 — 이 두 규칙이 「지연 N건」을 믿을 수 있게 만든다.

지연 섹션에서는 마감일을 일괄 재조정한다:

- 각 지연 태스크 앞의 체크박스로 대상을 고른다. 기본은 전체 선택.
- **선택 N건 → 오늘** 또는 **→ 다가오는 금요일** 버튼으로 마감일만 한 번에 변경한다(오늘이 금요일이면 금요일 버튼은 숨김). 확인 후 실행되며, 기존 `PATCH /api/tasks/:id`를 건별로 호출할 뿐 별도 API는 없다.
- 그 밖의 날짜는 옆의 **날짜 입력**으로 직접 고른다. 고르는 순간 같은 확인 절차를 거쳐 실행되며, 버튼과 완전히 같은 경로를 쓴다. 과거로 미루는 건 의미가 없어 `min`은 오늘이다.
- 시작일은 건드리지 않는다. 지연 태스크는 시작일 ≤ 기존 마감일 < 오늘이므로 어떤 재조정 날짜도 검증(시작일 > 마감일 거부)에 걸리지 않는다.

## 메모 (Keep 스타일)

태스크가 되기엔 이르거나 태스크가 아닌 것들을 담는 뷰. `notes` 전용 테이블을 쓰되, 라벨은 **기존 업무분류를 재사용**한다 — 사이드바 토글·분류 필터·색상 체계가 그대로 적용되고, 분류는 선택이라 없는 메모는 필터에 걸리지 않고 항상 보인다.

- **빠른 작성**: 상단 «메모 작성…»을 클릭하면 폼이 펼쳐지고, 바깥 클릭이든 Esc든 닫는 모든 경로가 저장이다(비어 있으면 그냥 닫힘).
- **고정·색상**: 고정 메모는 상단 «고정됨» 섹션에 모인다. 색상은 8색 파스텔 팔레트이며 고정·색상 변경은 수정 시각을 밀지 않는다 — 정렬(수정일 역순)이 흔들리지 않게.
- **보관**: 태스크 보관과 같은 `archived` 플래그. «보관 보기» 토글로 확인하고 복원한다.
- **삭제**: 태스크와 같은 5초 되돌리기 토스트.
- **태스크 연결**: 메모의 «연결 태스크»로 잇는다. 태스크 모달 하단에 연결된 메모가 보이고, 태스크를 지워도 메모는 남는다(연결만 해제).
- **태스크로 전환**: 카드의 ➜ 버튼이 제목·내용·분류를 프리필한 새 태스크 모달을 열고, 저장하면 그 태스크에 메모가 연결된다. 전환 전용 API는 없다 — 기존 API 2회 호출이다.
- 분류 이름을 바꾸면 메모의 분류도 따라온다. 분류를 **삭제**하면 태스크는 남은 첫 항목으로 이관되지만 메모는 분류 없음(NULL)이 된다 — 메모의 분류는 필수가 아니라서다.

## 경과 로그 (memo)

태스크 모달의 «설명 · 메모» 위에 **한 줄 입력**이 있다. 치고 Enter(또는 `경과 추가`)를 누르면 `MM/DD · 내용`이 memo **맨 위**에 붙는다. 최신이 위다.

스키마 변경은 없다. 실사용에서 memo를 이미 이렇게 쓰고 있었기 때문이다:

```
심준 대리 최종 피드백 + 애플리케이션 서비스화 요구건
→ 내부 논의 → 차주 중 회신하기로 약속
```

손으로 `→`를 찍던 걸 앱이 날짜와 함께 찍어줄 뿐이다.

- **기존 태스크는 즉시 저장**된다(체크리스트와 같은 규칙). 저장과 동시에 변경 스냅샷도 갱신하므로 모달을 닫을 때 «저장 안 한 변경» 확인창이 뜨지 않는다.
- **신규 태스크**는 아직 id가 없어 로컬에만 쌓이고, `저장`을 눌러야 함께 나간다.
- textarea는 그대로 둔다 — 잘못 찍은 줄을 지울 수단이 필요하다.
- MCP `weekly_review`의 각 항목에 memo **맨 윗줄**이 `note`로 붙는다. 주간보고 초안이 여기서 바로 나온다(메모가 없으면 키 자체가 없다).

### memo 안의 URL

목록 뷰의 memo 칸에서 `http(s)://…`가 자동으로 링크가 된다(`target=_blank` · `rel=noopener`). 업무가 ITSM·메일·문서에서 오는데 붙여넣어도 클릭이 안 됐다.

링크 변환은 **반드시 `esc()` 다음에** 돈다([public/app.js](public/app.js)의 `linkify`). 순서가 바뀌면 URL 안의 따옴표가 `href` 속성을 탈출한다. esc를 먼저 거치므로 `"`는 이미 `&quot;`라 속성을 깨지 못하고, `<img onerror=…>` 같은 건 그냥 텍스트로 남는다.

## 체크리스트

태스크 모달 하단에서 세부 항목을 관리한다. 체크·추가·삭제·순서 변경은 **즉시 저장**되며, 제목·날짜 등 나머지 필드는 기존대로 `저장` 버튼을 눌러야 반영된다. 신규 태스크는 저장 후에 항목을 추가할 수 있다.

항목은 드래그로 순서를 바꾼다. 끄는 방향에 따라 삽입선이 목표 항목의 위/아래에 표시되고, 놓으면 전체 순서를 서버가 `0..n-1`로 다시 매긴다.

진행률(`2/5`)은 목록 뷰 제목 아래 배지와 보드 카드 진행 바에 표시된다. 항목을 모두 체크해도 태스크 상태가 자동으로 `완료`로 바뀌지는 않는다 — 상태 전환은 항상 수동이다.

## 하위 태스크 (상하위 연결)

체크리스트가 «한 태스크 안의 세부 항목»이라면, 하위 태스크는 **태스크끼리의 연결**이다. 하위도 독립된 태스크라 자기 상태·마감일·담당 분류·체크리스트를 가진다.

- 모달의 **상위 태스크**에서 연결한다. 하위를 가진 태스크에는 이 필드 대신 안내가 뜬다.
- 상위 모달 하단의 **하위 태스크** 목록에서 하위를 클릭해 바로 열 수 있고, `＋ 하위 태스크 추가`는 열려 있던 수정 내용을 먼저 저장한 뒤 상위의 분류·마감일을 물려받은 새 태스크 모달을 연다. 같은 자리의 **프로젝트 뷰로 열기**도 먼저 저장한 뒤 이동한다.
- 깊이는 **1단계**까지다(Jira와 동일). 하위에 다시 하위를 붙일 수 없고, 하위를 가진 태스크는 다른 태스크의 하위가 될 수 없다. 이 규칙 하나로 자기참조·순환이 전부 막혀 그래프 탐색이 필요 없다.
- 목록 뷰는 하위를 상위 바로 아래에 들여쓰기해 붙이고(상위가 필터에 걸려 안 보이면 제자리에 남는다), 상위에는 `⑂ 1/3` 배지가 붙는다. 보드 카드는 하위에 왼쪽 세로선과 `↳ 상위 제목` 칩을(클릭하면 상위 태스크가 열린다), 상위에 `⑂` 태그를 표시한다.
- 하위 표시의 색은 **상위 태스크의 업무분류 색**을 CSS 변수 `--sub`로 물려받는다. 상하위 전용 색을 따로 박지 않는 이유는, 분류 색이 사용자 설정값이라 어떤 값을 고정해도 언젠가 겹치기 때문이다. 「하위다」라는 사실은 색이 아니라 **형태**(세로선·`↳` 칩·들여쓰기)가 알리고, 색은 「누구의 하위인가」만 말한다. 상위 쪽 `⑂ 1/3` 배지는 건수 정보라 무채색으로 두어 분류 색과 경쟁하지 않게 했다.
- 다만 **하위가 지연 중이면 그 배지는 경고색 + `⚠`**가 된다(`⑂ 0/1 ⚠`). 상위는 자기 마감이 멀어 평온해 보여도 하위가 밀려 있을 수 있는데, 목록·보드에서 그 사실이 전혀 드러나지 않았다. 목록·보드가 같은 마크업(`childBadge`)을 써서 규칙이 한 벌이다. **이 배지를 누르면 프로젝트 뷰가 열린다.**
- **상위를 삭제해도 하위는 지워지지 않는다**(`ON DELETE SET NULL`). 목록의 `×` 버튼에는 확인 절차가 없어 CASCADE는 위험하다. 연결만 끊기고 하위는 최상위 태스크로 남는다.

## 프로젝트 뷰 (`/project`)

**하위 태스크를 가진 태스크 = 프로젝트**다. 별도 플래그를 두지 않는다 — 하위가 붙는 순간 프로젝트가 되고, 마지막 하위를 떼면 그냥 태스크로 돌아간다.

전 태스크를 늘어놓던 «타임라인» 뷰를 메뉴에서 빼고 그 간트 렌더러를 여기로 돌렸다. 개인 업무 전체를 간트로 보는 건 과잉이었지만, **한 프로젝트의 하위들**을 볼 때는 실제로 쓸모가 있다.

메뉴에 없으므로 입구는 셋이다:

1. 목록의 `⑂ 1/3` 배지
2. 보드 카드의 `⑂` 태그
3. 태스크 모달 «하위 태스크» 헤더의 **프로젝트 뷰로 열기**

`/project`로 쿼리 없이 들어가면 **프로젝트 목록**이 나온다(하위를 가진 태스크 전체). 이 화면이 사실상 메뉴를 대신한다.

`/project?task=27` 화면 구성:

- **머리** — 상위 태스크의 제목·상태·분류·`⑂` 진행·마감. 제목을 누르면 상위 모달이 열린다.
- **간트** — 하위 1건당 1행. 오늘 기준선(붉은 실선)과 **상위 마감 기준선**(주황 점선)이 함께 그려지고, 상위 마감을 넘긴 하위는 막대가 경고색 + `⚠`가 된다.
- **날짜 인라인 편집** — 각 행 오른쪽의 시작일·마감일 입력. 고르는 순간 저장된다. **앱에서 시작일이 보이는 유일한 곳이다.**
- **완료 토글** — 행 왼쪽 체크박스. 가장 잦은 조작이라 모달을 열지 않는다.
- **일정 미정** — 마감 없는 하위는 막대를 그릴 수 없어 간트 아래 별도 구역에 모인다. 마감일을 채우면 위로 올라간다.
- **＋ 하위 태스크 추가** — 제목만 받는 인라인 입력. 보드 빠른 추가와 같은 규칙으로 닫는 모든 경로(Esc·바깥 클릭)가 저장이고, 상위의 분류를 물려받되 마감은 붙지 않는다.

이 뷰는 **분류 필터와 `완료 숨김`을 따르지 않는다**. 필터 때문에 프로젝트 안의 하위가 사라지면 일정이 거짓말을 하기 때문이다.

## 설정 항목 관리

헤더의 **설정** 버튼에서 **진행상황 · 업무분류**를 관리한다. 둘 다 하드코딩이 아니라 `options` 테이블의 한 종류(`kind`)이며, 추가·이름변경·색상변경·삭제·순서변경 규칙이 완전히 같다. 업무분류만 별도 테이블을 쓰던 구조는 폐기했다 — 규칙이 한 벌이면 분기도 한 벌이면 된다. 폐기한 `kind`(`type`·`priority`)로 요청하면 404다.

- **색상**: 항목마다 색을 고른다. 칩 배경은 같은 색의 10% 투명도로 자동 계산되므로 색을 두 번 고를 필요가 없다. 목록 칩·보드 카드·캘린더·프로젝트 뷰·요약 차트가 모두 이 색을 따른다. 업무분류 색은 사이드바 점과 보드 카드 태그에 쓰인다.
- **이름 변경**: 그 값을 쓰던 태스크도 함께 바뀐다. 참조가 끊기지 않는다.
- **삭제**: 그 값을 쓰던 태스크는 남은 첫 항목으로 옮겨진다. 마지막 하나는 지울 수 없다.
- **순서**: 드래그로 바꾼다. 진행상황 순서는 보드 열 순서(보드에서 열을 끌어도 같은 값이 바뀐다)가 된다.
- **완료 · 대기** 체크박스는 진행상황에만 있다. 아래 두 절을 참고.

태스크 모달에 있던 «새 업무분류 추가 / 현재 분류 삭제»는 없앴다. 분류 관리 창구를 설정 한 곳으로 모은다.

### 진행상황의 `done` 플래그

코드가 `'완료'`라는 **이름**에 의존하지 않도록, 각 진행상황에 `done` 플래그를 둔다. `done`으로 표시된 상태가 «끝남»의 정의이며 다음이 전부 이 플래그를 본다:

| 기능 | 동작 |
|------|------|
| 완료 숨김 | `done` 상태를 감춘다 |
| 보관 | `done` 상태만 보관 대상 |
| 반복 생성 | `done`이 아닌 상태 → `done`으로 넘어갈 때 다음 회차 생성 |
| `today_brief` | `done`이 아닌 것만 브리핑 |
| 완료 시각 | `done`으로 넘어갈 때 `done_at` 기록, 풀면 삭제 |
| 마감일 표시 | `done`이면 지연/D-day 대신 완료일을 회색으로 |
| 프로젝트 뷰 | 하위 완료 토글이 `done` 상태와 첫 미완료 상태를 오간다 |

덕분에 `완료`를 `Done`으로 바꾸거나 `취소` 같은 종료 상태를 추가해도 동작이 유지된다. `done` 상태가 하나도 남지 않는 변경(해제·삭제)은 거부한다 — 기준이 사라지면 위 기능이 전부 의미를 잃기 때문이다.

### 진행상황의 `waiting` 플래그

같은 자리에 붙는 «공이 남에게 있음» 표시. `done`과 짝을 이루지만 규칙이 두 가지 다르다 — **동시 지정 불가**(400), **하나도 없어도 됨**. 자세한 내용은 위 «대기 중» 절을 참고.

MCP 도구의 enum은 **서버 기동 시점**의 설정으로 고정된다. 설정을 바꿨다면 MCP 서버를 재시작해야 새 값을 쓸 수 있다(웹 UI는 즉시 반영).

## 완료 태스크 정리 (보관)

헤더의 **정리** 버튼에서 오래된 완료 태스크를 한 번에 보관한다. 삭제가 아니라 `archived` 플래그라 언제든 되돌릴 수 있다.

- 기준일을 고르면 **그 날짜 이전에 마감된 완료 태스크** 건수를 먼저 보여주고, 확인 후에만 옮긴다. 기본값은 30일 전.
- 미완료 태스크는 아무리 오래됐어도 보관하지 않는다.
- 보관된 태스크는 목록·보드·캘린더·요약 통계·`today_brief`에서 전부 빠진다.
- 같은 모달 하단에서 개별 **복원**과 **영구 삭제**를 할 수 있다.

기준은 **완료 시각**(`done_at`)의 날짜 부분이다. 그 값이 없는 구버전 행에서만 마감일을 근사치로 쓴다(`COALESCE(substr(done_at,1,10), due)`). 덕분에 마감이 한참 지난 일을 오늘 끝냈다면 오늘 끝낸 것으로 세고, 보관 대상에 바로 딸려 들어가지 않는다.

`완료 숨김` 토글과의 차이: 토글은 새로고침하면 풀리는 일시적 시야 정리이고, 보관은 지속되며 통계에서도 빠진다.

MCP에서는 `archive_tasks`(`before_days` 기본 30, `dry_run`으로 건수만 확인)와 `restore_task`를 쓴다. `list_tasks({ archived: true })`로 보관분을 조회한다.

## 반복 태스크

모달의 **반복** 필드에 주기를 지정하면(반복 없음 / 매일 / 매주 / 2주 / 4주), 해당 태스크를 `완료`로 바꾸는 순간 다음 회차가 자동으로 생성된다. 미리 여러 건을 만들어 두지 않으므로 목록이 불어나지 않는다.

다음 회차가 물려받는 것:

| 항목 | 규칙 |
|------|------|
| 마감일 | 직전 마감일 + 주기. 이미 지난 날짜가 되면 오늘을 넘길 때까지 주기를 더한다 |
| 시작일 | 시작~마감 간격을 그대로 유지 |
| 제목·분류·메모 | 그대로 복사 |
| 체크리스트 | 항목을 템플릿처럼 복사하되 **전부 미체크** |
| 상태 | 항상 `시작 전` |

- 늦게 완료해도 과거 날짜의 태스크가 생기지 않고, 원래 주기 격자는 유지된다. (7/17 마감 · 2주 주기를 7/28에 완료 → 다음 마감 7/31)
- 이미 완료된 태스크를 다시 수정해도 회차는 늘지 않는다. `완료`로 **넘어가는 순간**에만 생성된다.
- 체크리스트를 모두 체크해도 상태는 자동으로 바뀌지 않으므로, 반복이 저절로 돌지 않는다. 완료 처리는 항상 수동이다.
- 월 단위 반복은 지원하지 않는다. 주기가 일수라서 "매월 1일" 같은 달력 기준 규칙을 표현할 수 없다.

목록 뷰와 보드 카드에는 `🔁 2주마다` 배지가 붙는다. MCP에서는 `create_task` / `update_task`의 `repeat_days`(0이면 반복 없음)로 지정한다.

### 이전 회차 접기

회차가 쌓이면 같은 제목이 목록을 도배한다. **목록 뷰**는 한 계열의 완료 회차 중 **최신 하나만** 보여주고 나머지는 접는다. 최신 회차에 붙는 `＋ 이전 회차 3건` 배지를 누르면 펼쳐지고, `− 이전 회차 접기`로 되돌린다. 미완료 회차는 접지 않는다.

계열은 **주기 + 제목**으로 묶는다. 회차마다 별도 태스크로 복사될 뿐 계열 id가 없기 때문이며, 어느 회차의 제목을 고치면 그 건은 계열에서 떨어져 나온다. 접힘 상태는 저장하지 않아 새로고침하면 다시 접힌다.

보드·캘린더에는 적용하지 않았다. 그쪽은 `완료 숨김`과 보관이 같은 역할을 한다.

## 완료 시각 (`done_at`)

진행상황이 **`done`이 아닌 상태 → `done`으로 넘어가는 순간**에 시각이 찍힌다(`YYYY-MM-DD HH:MM:SS`). 반복 회차 생성과 정확히 같은 판정을 쓴다.

- 이미 완료된 태스크를 다시 저장해도 시각이 밀리지 않는다.
- 완료를 풀면(`done` → 그 외) `NULL`이 된다.
- 처음부터 `done` 상태로 **생성**하면 찍히지 않는다. 「넘어간」 적이 없기 때문이며, 읽는 쪽이 마감일로 갈음한다.
- 기존 DB는 첫 실행 때 컬럼만 추가되고 값은 `NULL`로 남는다. 마감일로 채워 넣으면 실제로 끝낸 시각을 지어내는 셈이라 그렇게 하지 않았다.

쓰이는 곳:

| 기능 | 동작 |
|------|------|
| 보관 | 완료 시각 기준으로 대상을 고른다 (없으면 마감일) |
| 마감일 표시 | 완료 건은 마감일이 아니라 **실제로 끝낸 날**을 보여준다 (`08/03 완료`) |
| 목록 정렬 | 마감일로 정렬할 때 완료 행은 화면에 보이는 값(완료일)으로 줄 세운다 |
| MCP `list_tasks` | 각 태스크에 `done_at`이 함께 온다 (미완료면 `null`) |

종전에는 완료 행에 마감일을 찍고 뒤에 「완료」만 붙여, 실제로 끝낸 날처럼 보이지만 아닌 값을 보여 주고 있었다.

### 폐기: 진척률 %

요약 뷰의 평균 진척률(`taskProgress` / `weightedPct`)은 없앴다. 태스크 44건에 체크리스트 항목이 3개뿐이라 «체크리스트를 반영한 평균»이 사실상 완료율과 같았고, 그마저도 근거가 없는 숫자였다. 요약은 **완료 건수 · 대기 건수**로만 말한다.

개별 카운트 배지(`☑ 2/5`)는 실제 정보가 있어 남긴다 — 목록 뷰 제목 아래와 보드 카드 진행 바. [public/progress.js](public/progress.js)에는 이제 집계 함수 둘(`checklist` / `checklistTotals`)만 있다.

분류별 카드의 막대는 **진행상황 분포**다.

## API

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/api/meta` | 설정 항목 2종 — statuses(이름·색상·순서·done·waiting) · categories |
| POST | `/api/options/:kind` | 설정 항목 추가 (`kind` = `status` 또는 `category`. 그 외는 404) |
| PATCH | `/api/options/:id` | 이름·색상·done·waiting 수정 (이름 변경 시 태스크 참조도 이동) |
| PATCH | `/api/options/:kind/order` | 순서 변경 |
| DELETE | `/api/options/:id` | 삭제 (쓰던 태스크는 남은 첫 항목으로 이관) |
| GET | `/api/tasks` | 전체 태스크 (마감일 순 · 마감 없음은 뒤), `subtasks` 배열 포함. `?archived=1`이면 보관분만 |
| GET | `/api/archivable?before=날짜` | 보관 대상 건수 미리보기 |
| POST | `/api/tasks/archive` | `{ before }` 이전 마감 완료분 일괄 보관 |
| POST | `/api/tasks` | 생성 (title·status·category·start 필수. due·memo·repeat_days는 선택) |
| PATCH | `/api/tasks/:id` | 부분 수정 — 모달 저장·드래그 상태 변경 공용 |
| DELETE | `/api/tasks/:id` | 삭제 (체크리스트 CASCADE, 하위 태스크는 연결만 해제) |
| POST | `/api/tasks/:id/subtasks` | 체크리스트 항목 추가 |
| PATCH | `/api/subtasks/:id` | 항목 수정 (`title` / `done`) |
| PATCH | `/api/tasks/:id/subtasks/order` | 순서 변경. `{ ids: [...] }`에 해당 태스크의 **전체** 항목 id를 원하는 순서로 |
| DELETE | `/api/subtasks/:id` | 항목 삭제 |
| GET | `/api/notes` | 메모 목록 (고정 우선 → 수정일 역순). `?archived=1` `?q=` `?category=` `?task_id=` |
| POST | `/api/notes` | 메모 생성 (title/body 중 하나 필수) |
| PATCH | `/api/notes/:id` | 부분 수정 (고정·색상·보관·태스크 연결 포함) |
| DELETE | `/api/notes/:id` | 삭제 |

분류 전용 라우트(`/api/categories`)는 없앴다. `kind=category`로 위의 `/api/options/*`를 그대로 쓴다.

입력은 서버에서 검증한다: 진행상황은 화이트리스트, 마감일은 비울 수 있고(«언젠가»), 날짜는 `YYYY-MM-DD`, 시작일 > 마감일이면 400. 상위 태스크는 `parent_id`로 생성·수정 양쪽에서 지정하며(`null`이면 해제), 1단계 위반·자기참조·없는 상위는 400이다.

`/api/tasks`는 태스크당 조회하지 않고 subtasks를 한 번에 읽어 묶는다(N+1 회피).

## MCP 서버

Claude Code에서 태스크·체크리스트를 직접 다룰 수 있다. 프로젝트 루트의 `.mcp.json`이 등록 설정이며, 다른 디렉토리에서도 쓰려면 `~/.claude.json`의 `mcpServers`에 같은 항목을 넣는다.

```json
{ "mcpServers": { "mywork": { "command": "node", "args": ["D:\\Personal\\MyWork\\mcp.js"] } } }
```

| 도구 | 설명 |
|------|------|
| `list_tasks` | 조회. `status`·`category`·`q`·`due_before`·`overdue` 필터, subtasks 포함 |
| `create_task` | 생성. `title`만 필수. due를 안 주면 마감 없음. `parent_id`로 하위 태스크 생성 |
| `update_task` | 부분 수정. `parent_id`로 상위 연결·해제(`null`) |
| `delete_task` | 삭제 (체크리스트 CASCADE, 하위 태스크는 연결만 해제) |
| `add_subtask` / `update_subtask` / `delete_subtask` | 체크리스트 항목 |
| `list_categories` | 분류별 태스크 수 |
| `today_brief` | 오늘 기준 브리핑 — 미완료를 지연 / 오늘 마감 / 예정 / 언젠가 / 대기로 나눠 반환 |
| `weekly_review` | 기간 안에 **끝낸 일** — 주간보고·회고용. 기본 구간은 이번 주 월요일~오늘 |
| `list_notes` / `create_note` / `update_note` / `delete_note` | 메모 CRUD. `task_id`로 태스크 연결, `archived`로 보관 |

- `overdue: true`는 **마감 지남 + 미완료**만 반환한다. 완료된 지난 태스크는 빠진다.
- `today_brief`는 `days`(기본 7)로 예정 구간을, `category`로 범위를 좁힐 수 있다. 각 항목은 판단에 필요한 필드만(제목·분류·상태·마감·진행률) 담고 `late_days` / `d_day`가 붙는다. 마감 없는 건은 `someday`, 대기 상태는 `waiting`으로 빠지고 지연에 세지 않는다. 창 밖의 미완료 건수는 `summary.later`로만 센다.
- `weekly_review`는 `today_brief`의 반대편이다. 브리핑이 «뭐가 남았나»라면 이쪽은 «뭘 끝냈나»다.
  - `weeks_ago: 0`(기본)은 이번 주 월요일~오늘, `1`은 지난 주 월~일. `since`/`until`로 구간을 직접 줄 수도 있다.
  - `completed`에는 제목·분류·끝낸 날·`note`(memo 맨 윗줄)가, `carried_over`에는 그 구간이 마감이었는데 아직 안 끝난 것(=이월)이 담긴다. 이월 건 중 대기 상태에는 `waiting: true`가 붙는다.
  - **보관된 태스크도 센다.** 끝낸 일을 빠뜨리는 게 회고 도구의 최악의 실패라서다.
  - `done_at`이 없어 마감일로 갈음한 건에는 `estimated: true`가 붙는다. 이 기능을 넣기 전에 완료한 태스크가 전부 여기 해당한다.
- `create_task` / `update_task`에 없는 분류명을 주면 분류를 새로 만든다.
- 웹 서버와 DB 파일을 공유한다(WAL + `busy_timeout`). MCP로 바꾼 내용은 **브라우저를 새로고침해야** 보인다.
- **설정(진행상황·업무분류)을 바꾸면 MCP 서버를 재시작해야 한다.** 도구 스키마의 `status` enum은 기동 시점의 DB 값으로 굳고, 도구 목록은 연결당 한 번만 전송된다. 재시작 전에는 새로 만든 상태를 `create_task`에 줄 수 없다.
- `MYWORK_DB_PATH`로 DB 경로를 바꿀 수 있다. 웹 서버(`server.js`)도 같은 환경변수를 본다.

### 아침 브리핑 자동화

평일 아침 08:30(KST)에 `today_brief`를 돌려 브리핑을 받는 루틴을 등록해 뒀다. 크론은 UTC라 `30 23 * * 0-4`(전날 23:30 UTC)다. 결과는 <https://claude.ai/code/routines>에서 본다.

로컬 DB를 읽어야 하므로 **브리지 환경**(로컬 `D:\Personal\MyWork`에 붙는 환경)으로 돌린다. 일반 클라우드 환경은 `data/mywork.db`가 git에 없어 아무것도 못 읽는다. 루틴 프롬프트는 MCP `today_brief`를 먼저 쓰고, 안 되면 `store.listTasks`를 직접 호출하도록 되어 있으며, 둘 다 실패하면 브리핑을 지어내지 말고 실패를 보고하게 해 뒀다. 읽기 전용이라 태스크를 만들거나 고치지 않는다.

## 데이터

`data/mywork.db`에 저장. **DB 파일이 새로 만들어질 때만** 예시 태스크 15건과 기본 분류 8종이 들어간다(태스크를 전부 지워도 다시 생기지 않음). 초기화하려면 `data/` 디렉토리를 삭제하고 재실행.

기존 DB는 첫 실행 때 자동 이관된다: `categories` 테이블의 분류가 순서 그대로 `options(kind='category')`로 옮겨지고 구 테이블은 삭제된다. 분류에 색이 없었으므로 기본 팔레트를 순서대로 입힌다. 이관 후에는 **웹 서버와 MCP 서버를 모두 재시작**해야 한다(구버전 프로세스는 사라진 테이블을 계속 조회한다).

### 백업 — `cp`가 아니라 `VACUUM INTO`

WAL 모드라 최근 쓰기가 `mywork.db-wal`에 있고 `mywork.db` 본체에는 아직 없다. **파일을 복사하면 텅 빈 DB를 얻는다.**

```bash
node -e "new (require('node:sqlite').DatabaseSync)('data/mywork.db').exec(\"VACUUM INTO 'data/backup.db'\")"
```

`VACUUM INTO`는 WAL을 반영한 일관된 스냅샷을 만들고, 열려 있는 서버를 멈출 필요도 없다. 복원은 반대로 파일을 되돌려 놓으면 된다(이때는 서버를 내리고 `-wal`·`-shm`도 함께 지운다).
