# 부드러운(Things풍) UI 전면 적용 + 요약·목록 재구성

2026-10-12 · 승인됨 · 앞선 설계 `2026-10-12-linear-redesign-design.md`를 톤 면에서 대체한다

## 목표

피드백: «나머지 뷰가 촌스럽다», «한눈에 안 들어온다», «디자인도 촌스럽다».
앱을 열었을 때 가장 먼저 알아야 하는 것은 **오늘 뭘 해야 하나**다.

시각 비교(A Linear 정제 / B 부드러운 Things풍 / C Raycast풍 고밀도)에서 **B**를 골랐다.
요약은 «한 줄기 오늘», 목록은 «묶음 리스트», 나머지 뷰는 구조를 유지하고 톤만 맞춘다.

범위: 토큰 · 사이드바 · 헤더 · 요약 · 목록 · 보드 · 캘린더 · 메모 · 프로젝트 · 모달 · 토스트.
범위 밖: 등록 입구(AI 초안 입력), 서버·스키마 변경 일체.

## 접근

토큰과 공통 컴포넌트(판·알약·버튼)를 먼저 바꾸고, 뷰를 하나씩 바꾼다. 뷰마다 커밋하고 `npm test`를 돌린다.
기각안: 한 번에 전부 교체하는 방식. 깨진 곳을 찾기 어렵다.

## 1. 토큰 (`public/style.css` `:root`)

| 토큰 | 라이트 | 다크 | 비고 |
|---|---|---|---|
| `--bg` (앱 배경) | `#F4F4F6` | `#0F1115` | 회색 앱 배경을 되살린다. 콘텐츠는 그 위의 흰 판 |
| `--surface` (판·카드·모달) | `#FFFFFF` | `#16191E` | **변경 금지** — 팔레트 3:1 대비가 이 값을 기준으로 잡혀 있다 |
| `--side-bg` | `= --bg` | `= --bg` | 사이드바와 본문 배경을 한 톤으로 맞춘다. 경계선 제거 |
| `--radius` | `12px` | | 판·카드. 모달은 `16px`, 캘린더 칸은 `8px` |
| `--elev` | `0 1px 2px rgb(0 0 0/.04), 0 4px 14px rgb(0 0 0/.04)` | `0 0 0 1px var(--line)` | 다크에서는 그림자가 안 보이므로 1px 테두리로 대신한다 |
| `--elev-lg` | `0 10px 40px rgb(0 0 0/.12)` | `0 10px 40px rgb(0 0 0/.5)` | 모달 |
| `--accent` 계열 | 기존 유지 | 기존 유지 | 인디고 `#5E6AD2` / `#8B93F5` |

- `light-dark()`는 색 값에만 쓸 수 있어 그림자 전체를 분기할 수 없다. 그래서 색 토큰 두 개로 나눈다:
  `--elev-c: light-dark(rgb(0 0 0/.04), transparent)`, `--elev-ring: light-dark(transparent, var(--line))`,
  `--elev: 0 0 0 1px var(--elev-ring), 0 1px 2px var(--elev-c), 0 4px 14px var(--elev-c)`. 미디어쿼리를 두 벌 두지 않는다.
- 기존 `--surface-3`(보드 열 배경)은 쓰지 않는다. 보드 열은 투명하게 두고 카드만 흰 판으로 띄운다.

### 알약(pill)

`.pill`: `padding:1px 8px; border-radius:99px; font-size:11.5px; font-weight:500`.

- **색 규칙은 기존 `.tint`를 그대로 쓴다**(`--c` 인라인, 배경 14% 혼합, 글자 명도 보정 — 커밋 6c9b64c에서 대비 보정 완료).
  알약은 `.chip`의 모양(반경·여백)만 바꾼다. 분류 알약은 분류색, 상태 알약은 상태색.
- 대비 검증: 혼합 규칙을 바꾸지 않으므로 기존 검증이 유효하다. 브라우저에서 라이트/다크 각 1회 계산으로 확인만 한다.

### 버튼

주 버튼(`+ 새 태스크`, 저장)과 보조 버튼(`btn-sm`)은 `border-radius:99px`로 바꾼다. 아이콘 버튼은 원형 32px.

### 타이포

| 용도 | 크기/굵기 |
|---|---|
| 요약 «오늘» 제목 | 24px / 700, `letter-spacing:-.03em` |
| 그룹 제목 | 13px / 700 (지연 `--danger`, 오늘 `--warn`, 나머지 `--text`) + 개수 `--text-4` 500 |
| 행 제목 | 13px / 500 |
| 메타·메모 한 줄 | 12px / 400 `--text-4` |

## 2. 틀

- **사이드바**: 배경을 `--bg`로 바꾸고 오른쪽 경계선을 없앤다. 활성 메뉴는 `--surface` 배경 + `--elev`(떠 있는 흰 알약).
- **헤더**: 배경 투명(`--bg`), 아래 경계선 제거. 검색 입력·select는 흰 알약 + `--elev`. 아이콘 버튼은 원형.
- **본문**: 뷰 콘텐츠는 `--bg` 위에 놓고, 의미 단위마다 `.panel`(흰 판, `--radius`, `--elev`)으로 감싼다.
  기존 `.card`를 `.panel` 규칙으로 바꾼다(클래스명은 유지해도 된다 — 바꾸는 쪽이 diff가 크면 유지).

## 3. 요약 뷰 — «한 줄기 오늘»

```
오늘                                        (24px)
10월 12일 월요일 · 지연 3 · 미완료 12          (13px --text-3)

┌ 지연 3                        모두 미루기 ▾ ┐
│ ○ 제목                    [분류]    42일 지연 │
└────────────────────────────────────────────┘
┌ 오늘 마감 n ┐  ┌ 이번 주 n ┐  ┌ 대기 · 남의 차례 n ┐
› 언젠가 4          (접힘)
› 분류별 현황        (접힘 — 기존 스택바 + 범례)
```

- 통계 카드 4개(`.stats`)를 없앤다. 요약 문장에는 0이 아닌 항목만 넣는다(`지연 3 · 오늘 1 · 미완료 12`).
- 그룹 버킷 정의는 기존 그대로다(`late` / `dueToday` / `week` / `waiting` / `someday`). 빈 그룹은 그리지 않는다.
- «7일 이후 마감 미완료 n건» 힌트는 이번 주 그룹 아래에 흐린 한 줄로 유지한다.
- **언젠가 · 분류별 현황**은 `<details>`로 접는다. 펼침 상태는 `localStorage['mywork.summary.open']`에 저장한다.
- **모두 미루기 ▾**: 지연 그룹 머리 오른쪽에 둔다. 누르면 작은 메뉴가 뜬다: `오늘` · `금요일(MM/DD)` · 날짜 입력.
  고르는 즉시 지연 전체에 기존 `reschedule(to)`를 실행한다. 행별 선택(`reSel`)과 체크박스는 없앤다.
  `S.reSel`·`lateSelected()`·`data-act="resel"` 경로를 제거하고 `lateOpen()`을 직접 쓴다.
- 빈 상태: 미완료가 0이면 «오늘 할 일이 없습니다» 판 하나만 보여 준다.

## 4. 동그라미 = 완료 (요약·목록 공통)

- 행 맨 앞에 18px 원형 버튼 `data-act="complete" data-id`를 둔다(`aria-label="완료 처리"`).
- 누르면 다음 순서로 동작한다.
  1. 화면에서 즉시 체크 표시·취소선·`opacity:.5`.
  2. 토스트 «완료함 · 되돌리기».
  3. **5초 뒤** `PATCH /api/tasks/:id {status: <첫 done 상태>}`로 확정한다.
- 기존 삭제 지연 확정(`S.pending`, `commitDelete`, `undoDelete`, `pagehide` 플러시)을 `kind: 'complete'`로 확장한다.
  토스트는 하나뿐이므로 대기 중에 다른 완료·삭제가 들어오면 앞의 건을 먼저 확정한다.
- 서버 반영을 미루는 이유: 반복 태스크는 완료 PATCH 때 서버가 다음 회차를 만든다. 즉시 반영하고 되돌리면 다음 회차가 남는다.
- 완료 상태는 `S.statuses.find(isDone)`로 고른다. done 상태가 없으면 버튼을 그리지 않는다.
- 완료 행의 동그라미를 다시 누르면 «미완료로» 되돌린다. 첫 미완료 상태로 즉시 PATCH하며, 이쪽은 되돌리기 대기가 필요 없다.

## 5. 목록 뷰 — 묶음 리스트

- 열 머리 표(`COLS`, 열 클릭 정렬)를 없앤다. 뷰 상단에 세그먼트 탭 `상태별 | 분류별 | 마감순`을 둔다.
  선택은 `localStorage['mywork.list.group']`에 저장하고, 기본값은 `상태별`이다.
- **상태별**: 진행상황 설정 순서대로 그룹을 만들고, done 상태 그룹은 맨 아래에 둔다.
- **분류별**: 분류 설정 순서대로 그룹을 만들고, 그룹 안에서 미완료 → 완료 순으로 놓는다.
- **마감순**: 그룹 없이 판 하나에 담는다. 완료 행은 하단에 둔다(기존 규칙).
- 그룹 안 정렬은 모두 `byDue`다.
- 행 구성: `○ | 제목 + (메모 첫 줄, 흐리게, 말줄임) | [분류 알약] | 마감(dueMeta.text 색)`.
  - 상태별 그룹에서는 분류 알약을, 분류별 그룹에서는 상태 알약을 보여 준다. 마감순은 둘 다 보여 준다.
  - 체크리스트·하위 진척은 제목 줄 뒤에 `☑ 1/3` · `하위 1/2`로 붙인다(기존 `childBadge` 재사용).
  - 하위 태스크는 상위 바로 아래에 `padding-left:28px`로 들여쓴다. 왼쪽 주황 막대는 없앤다.
    단, 하위의 상태·분류가 상위와 달라 다른 그룹에 속하면 그 그룹에 일반 행으로 두고 `↳ 상위 제목`을 메모 줄에 표시한다.
  - 삭제 `×`는 hover·포커스 때만 보인다(기존 `requestDelete` 유지).
- 행 클릭은 편집 모달(`data-act="open"`), 동그라미는 완료다.
- 빈 상태: «조건에 맞는 태스크가 없습니다».

## 6. 보드

- 열 배경은 투명, 머리는 `색 점 + 이름(700) + 개수 + 오른쪽 +`. 기존 기능은 유지한다.
- 카드: `--surface` + `--radius` + `--elev`, 테두리 없음. hover 시 그림자를 조금 진하게.
- 카드 메타의 분류는 알약으로 표시한다. 마감은 기존 `boardDue` 그대로.
- 드롭 대상 열은 `--accent-bg` 배경 + `--radius`.

## 7. 캘린더

- 그리드 선을 없애고, 날짜 칸을 `--surface` 둥근 타일(`8px`, 간격 4px)로 바꾼다. 이번 달이 아닌 날은 `opacity:.5`.
- 오늘 날짜 숫자는 인디고 원(`--accent` 배경, `--on-accent` 글자).
- 이벤트 칩은 분류 알약 색 규칙을 따른다(반경 5px). 지연 건은 `--danger-bg`/`--danger`.
- 월 이동 버튼은 원형 아이콘 버튼.

## 8. 메모

- 메모 카드: `--radius` + `--elev`, 테두리 없음. 색 메모는 기존 배경색을 유지한다.
- 빠른 작성 입력은 흰 알약 판 + `--elev`.

## 9. 프로젝트 뷰

- 프로젝트마다 `.panel`로 감싼다. 칩은 알약 규칙을 따른다. 간트 막대 반경은 99px.

## 10. 모달·토스트

- 모달: 반경 16px, `--elev-lg`, 배경 딤은 기존 유지.
- 제목 입력은 테두리 없이 18px/700로 둔다. 그 아래 필드 줄은 기존 select·date 입력을 **알약 모양으로 스타일링**한다(요소·id 유지).
- 메모 textarea는 `--surface-2` 배경 + 반경 10px, 테두리 없음.
- 하단 버튼은 알약. 저장은 액센트 채움, 삭제는 `--danger` 글자.
- 설정·보관·AI 지시 모달도 같은 판·알약 규칙을 따른다.
- 토스트: 반경 99px, `--inv-bg` 유지.

## 11. 불변 조건

- 동작 변경은 §3(일괄 미루기 UI, 선택 제거), §4(완료 버튼), §5(목록 그룹·탭)뿐이다. 나머지는 스타일만 바꾼다.
- 모든 요소 `id`, 남아 있는 `data-act`·`data-drop`·`data-opt`를 유지한다. 단축키(`/`, `n`, `i`, `Ctrl+Enter`)를 유지한다.
- 반응형 브레이크포인트(1100 / 960 / 560px)를 유지한다. 목록이 표가 아니게 되므로 **목록은 폰에서도 세로로 읽힌다**(가로 스크롤 예외 해제). README의 해당 문장을 갱신한다.
- 새 의존성 없음. `light-dark()` 단일 토큰 체계 유지.

## 12. 검증

- `npm test` 통과(REST·MCP·진척 단위).
- 대비: `--bg` 위 `--text-4` 4.5:1(라이트/다크) — `--bg`가 바뀌므로 재계산. 알약은 `.tint` 그대로라 확인만.
- 수동 확인: 완료 → 되돌리기, 완료 → 5초 → 반영(반복 태스크는 다음 회차 1건만 생성), 완료 대기 중 뷰 이동(pagehide 플러시),
  모두 미루기 3경로, 목록 탭 3종 + 새로고침 후 유지, 보드 드래그·빠른 추가.
- 스크린샷: 전 뷰 × 라이트/다크 × 1440px, 요약·목록은 375px 추가.
- README의 «뷰» 절과 디자인 설명 문단을 갱신한다.
