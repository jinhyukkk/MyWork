# MyWork 재초점 계획 — 「프로젝트 관리」에서 「흩어진 업무 관리」로

작성일: 2026-08-03

## 배경

앱은 프로젝트 관리 도구로 출발했지만 실제 목적은 **여러 채널로 흩어져 들어오는 개인 업무를 잃지 않고 관리하는 것**이다. 실 사용 데이터(44건)가 그 미스매치를 이미 보여준다.

| 축 | 실제 분포 | 판정 |
|---|---|---|
| 우선순위 | Medium 40 / High 4 / Low 0 | 죽음 |
| 업무유형 | 개발 18 + 기획·문서 20 = 86% | 죽음 |
| 업무분류 | 인사시스템 12 / 유진GPT 31 / 기타 1 | 살아있음 |
| 진행상황 | 아이디어·할 일·검토 중을 **직접 추가**해 5단계 | 가장 많이 쓰는 축 |
| 시작일 | 대부분 생성일 근처 placeholder | 프로젝트성 업무에서만 의미 |
| 마감일 | 8/07·8/14·8/31·12/31에 집중 | 대부분 가짜(기본값 +7일, 「언젠가」의 도피처) |
| 체크리스트 | 44건에 3개 항목 | 안 씀 |
| 하위 태스크 | 2건 | 안 씀 — **전용 화면이 없어서** |
| memo | 44건 중 28건(64%) | 가장 많이 쓰는 선택 필드. 내용은 **경과 로그** |

핵심 문제 두 가지:

1. **가짜 마감일이 「지연」 숫자를 오염시킨다.** 마감일이 필수라 「언젠가 할 일」이 `12/31`, `8/31`을 달고 있고, 그 결과 요약 뷰의 지연 카운트가 신뢰를 잃는다.
2. **「공이 누구에게 있나」를 표현할 수 없다.** `심준 대리 회신`, `ITSM 등록 필요` 같은 남의 차례 업무가 내 할 일과 같은 줄에 서 있다.

## 목표

- 죽은 축(우선순위·업무유형)을 없애 캡처 마찰을 줄인다.
- 마감 없는 업무를 1급 시민으로 만든다.
- 「대기 중(남의 차례)」을 표현하고 지연 계산에서 분리한다.
- 손으로 쓰던 경과 로그를 앱이 찍는다.
- 하위 태스크를 **프로젝트 뷰**로 살린다(간트 재활용).

## 결정 사항

| 항목 | 결정 |
|---|---|
| 우선순위 | 코드에서 전면 제거. `tasks.priority` 컬럼은 방치(DEFAULT 유지), `options`의 `kind='priority'` 행만 삭제 |
| 업무유형 | 코드에서 전면 제거. `tasks.type` 컬럼 방치, `options`의 `kind='type'` 행만 삭제 |
| 시작일 | **컬럼 유지, 노출만 프로젝트 뷰로.** 태스크 모달·목록·보드에서는 사라지고 하위 태스크 관리 화면에서만 편집·표시 |
| 타임라인 뷰 | 메뉴에서 제거. 간트 렌더러를 **프로젝트 뷰**(하위 태스크 관리)로 전환 |
| 하위 태스크 | **유지·강화**. 프로젝트 뷰의 주인공 |
| 체크리스트 | 유지. 다만 진척률 % 계산은 제거하고 `2/5` 카운트만 남김 |
| 마감일 | `NULL` 허용. 테이블 재생성 마이그레이션 |
| 대기 상태 | `options`에 `waiting` 플래그 추가(`done`과 같은 패턴) |
| 경과 로그 | 스키마 변경 없음. `memo` 맨 앞에 `MM/DD · 내용` 한 줄을 붙이는 UI |

컬럼을 DROP하지 않는 이유: 되돌릴 수 없는 데이터 삭제인데 얻는 게 없다. `NOT NULL DEFAULT`가 있어 INSERT에서 생략해도 자동으로 채워진다.

## Phase 2 — 마감일 없음 허용

### 마이그레이션 (db.js `migrate()`)

`due TEXT NOT NULL`은 `ALTER COLUMN`으로 못 바꾼다. 테이블 재생성이 필요하다.

```js
// due를 NULL 허용으로. 한 번만 실행된다 — 재생성 후에는 notnull=0이라 조건이 거짓이 된다.
const dueCol = db.prepare('PRAGMA table_info(tasks)').all().find((c) => c.name === 'due');
if (dueCol?.notnull) {
  db.exec('PRAGMA foreign_keys = OFF');
  db.exec(`
    BEGIN;
    CREATE TABLE tasks_new (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      title TEXT NOT NULL,
      type TEXT NOT NULL DEFAULT '개발',
      status TEXT NOT NULL DEFAULT '할 일',
      category TEXT NOT NULL DEFAULT '기타',
      priority TEXT NOT NULL DEFAULT 'Medium',
      start TEXT NOT NULL,
      due TEXT,                                  -- ← NULL 허용
      memo TEXT NOT NULL DEFAULT '',
      repeat_days INTEGER NOT NULL DEFAULT 0,
      archived INTEGER NOT NULL DEFAULT 0,
      parent_id INTEGER REFERENCES tasks_new(id) ON DELETE SET NULL,
      done_at TEXT,
      created_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
    );
    INSERT INTO tasks_new
      SELECT id,title,type,status,category,priority,start,due,memo,
             repeat_days,archived,parent_id,done_at,created_at FROM tasks;
    DROP TABLE tasks;
    ALTER TABLE tasks_new RENAME TO tasks;
    COMMIT;
  `);
  db.exec('PRAGMA foreign_keys = ON');
  db.exec('CREATE INDEX IF NOT EXISTS idx_tasks_due ON tasks(due)');
  db.exec('CREATE INDEX IF NOT EXISTS idx_tasks_parent ON tasks(parent_id)');
}
```

- 자기참조 FK는 `REFERENCES tasks_new(id)`로 쓴다 — `RENAME TO tasks` 시 SQLite가 참조명을 함께 고친다. `tasks(id)`라고 쓰면 `DROP TABLE tasks`에서 깨진다.
- `subtasks.task_id`와 `notes.task_id`는 테이블 **이름**을 참조하므로 RENAME 후 정상 복구된다. `PRAGMA foreign_keys = OFF` 구간이 필요한 이유가 이것.
- `CREATE TABLE IF NOT EXISTS tasks` 블록의 `due`도 `TEXT`로(새 DB용).

**검증**: 마이그레이션 직후 `PRAGMA foreign_key_check` 무결 + 행 수 44/3/17/0 일치 + `PRAGMA table_info(tasks)`에서 `due.notnull = 0`.

### store.js
- `FIELDS.due`를 「`null`이거나 `YYYY-MM-DD`」로 완화. 빈 문자열은 `null`로 정규화.
- `createTask` / `updateTask`의 시작일 검증을 `if (data.due && data.start > data.due)`로.
- `listTasks`의 `ORDER BY due, id` → `ORDER BY due IS NULL, due, id` (마감 없음이 맨 뒤로).
- `filter.due_before` 절에 `t.due &&` 가드.
- `endedOn(t)`: `done_at`도 `due`도 없으면 `created_at`의 날짜 부분으로 폴백.
- `spawnNext`: `due`가 없는 태스크는 다음 회차를 만들지 않는다(주기를 더할 기준이 없다). 저장 시 「반복은 마감일이 있어야 합니다」로 거부하는 대신, 반복+마감없음 조합을 400으로 막는 게 명확하다.
- `archiveCompleted` / `countArchivable`: 이미 `COALESCE(substr(done_at,1,10), due)`를 쓰므로 둘 다 NULL이면 대상에서 빠진다 — 의도한 동작(끝난 날을 모르면 보관 기준을 세울 수 없다). 주석으로 명시.

### public/app.js
`due` 비교가 있는 모든 지점에 `!t.due` 가드를 넣는다. 대상:

| 위치 | 변경 |
|---|---|
| `dueMeta(t)` | `!t.due` → `{ text: '—', color: '#9AA3AF' }` |
| `endDate(t)` | `t.due ?? ''` |
| `lateOpen()` | `t.due && t.due < TODAY` |
| `viewSummary`의 late / dueToday / week | 각 절에 `t.due &&`. 마감 없는 미완료는 **«언젠가» 버킷**으로 |
| `viewList` 정렬 | 마감 없음을 항상 하단(완료 행 위) |
| `viewCalendar` | `t.due` 없으면 배치하지 않음 |
| `openNew` / `saveQuickTask` | **기본 마감일을 `null`로**. 가짜 마감의 근원 |
| 모달 `d-due` | `required` 제거, 옆에 「마감 없음」 표시 |

## Phase 5 — 타임라인 → 프로젝트 뷰

### 개념
**하위 태스크를 가진 태스크 = 프로젝트.** 별도 플래그를 만들지 않는다. 하위가 붙는 순간 프로젝트가 되고, 마지막 하위를 떼면 그냥 태스크로 돌아간다.

### 라우팅
- `public/timeline.html` → `public/project.html`로 파일명 변경, `data-view="project"`.
- 진입은 `/project?task=27`. 쿼리가 없으면 **프로젝트 목록**(하위를 가진 태스크 전체)을 보여준다.
- `VIEWS`에서 `timeline` 삭제 → 메뉴는 요약·목록·보드·캘린더·메모 5개.
- `S.projectId = new URLSearchParams(location.search).get('task')`.

메뉴에 없으므로 **진입점 3곳**을 만든다:
1. 목록의 `⑂ 1/3` 배지 → `/project?task=<id>` 링크로.
2. 보드 카드의 `⑂` 태그 → 동일.
3. 태스크 모달 «하위 태스크» 섹션 헤더에 `프로젝트 뷰로 열기` 링크. 열려 있던 수정 내용은 `＋ 하위 태스크 추가`와 같은 방식으로 **먼저 저장**한 뒤 이동.

### `viewProject(taskId)` — `viewTimeline`을 개조
기존 간트 렌더러(월 눈금 · 오늘 기준선 · `left/width` 계산)를 그대로 쓰되 입력이 달라진다.

```
입력: 상위 태스크 1건 + childrenOf(id)
축  : min(하위 시작일) ~ max(하위 마감일, 상위 마감일)
행  : 하위 태스크 1건당 1행
```

- **헤더**: 상위 제목 · 분류 칩 · 상태 · 마감(없으면 「마감 없음」) · `⑂ 1/3` 진행. 클릭하면 상위 태스크 모달.
- **상위 마감 기준선**: 오늘 기준선(점선)과 별개로 세로선 하나. 하위가 상위 마감을 넘으면 그 막대를 경고색으로.
- **마감 없는 하위**: 막대를 그릴 수 없다. 간트 하단에 **「일정 미정」 섹션**으로 따로 모으고 각 행에 날짜 입력 2개를 둔다. 날짜가 채워지면 위 간트로 올라온다.
- **인라인 편집**: 각 행 우측에 `시작일` · `마감일` date 입력. 변경 즉시 `PATCH /api/tasks/:id`. **여기가 앱에서 시작일이 보이는 유일한 곳.**
- **상태 토글**: 행 좌측 체크박스로 done 상태 전환(가장 잦은 조작).
- `＋ 하위 태스크 추가`: 제목만 받는 인라인 입력(보드 빠른 추가와 같은 규칙 — Esc·바깥 클릭도 저장). 상위의 분류를 물려받고 **마감일 없이** 생성된다.

### 프로젝트 목록 (`/project`, 쿼리 없음)
하위를 가진 태스크를 카드로 나열: 제목 · 분류 · `⑂ 2/5` · 상위 마감 · 지연 하위가 있으면 `⚠`. 클릭하면 해당 프로젝트 뷰. 하나도 없으면 「하위 태스크를 붙이면 여기에 프로젝트로 나타납니다」 안내.

### 시작일 노출 이동 (D2')
- 태스크 모달의 `d-start` 삭제. `syncDraft`·`TASK_FIELDS`에서도 제거.
- `COLS`의 `{key:'start'}` 삭제.
- `openNew` / `saveQuickTask`는 `start: TODAY`를 **계속 보낸다**(컬럼이 `NOT NULL`).
- 프로젝트 뷰의 date 입력만이 유일한 편집 경로.

### 정리
- README의 「타임라인」 항목을 「프로젝트 뷰」로 교체.
- `style.css`의 `.gantt-*`, `.g-row`, `.bar2` 등은 재사용. 프로젝트 헤더·미정 섹션용 클래스만 추가.

**검증**: `투자심의AI`(id 27)에 하위 2~3건을 붙여 프로젝트 뷰가 그려지는지, 마감 없는 하위가 미정 섹션에 가는지, date 입력이 즉시 반영되는지, 하위를 전부 떼면 프로젝트 목록에서 사라지는지.

## Phase 6 — 경과 로그 · URL 링크화

### 경과 로그 (A3)
`memo`를 append-only 로그로 쓰는 UI. **스키마 변경 없음.**

- 태스크 모달의 memo textarea **위**에 한 줄 입력 + `추가` 버튼.
- Enter 또는 버튼 → `memo = "MM/DD · <내용>\n" + memo` (최신이 위).
- 기존 태스크(`id` 있음)는 **즉시 저장**(체크리스트와 같은 규칙). 신규 태스크는 로컬 상태에만 쌓고 저장 시 함께 나간다.
- textarea는 그대로 남긴다 — 잘못 찍은 줄을 지울 수단이 필요하다.

이미 손으로 하던 것(`→ 내부 논의 → 차주 중 회신 약속`)을 앱이 날짜와 함께 찍는 것뿐이다.

### URL 링크화 (A4)
`memo`가 텍스트로 렌더되는 곳은 목록 뷰의 마지막 컬럼 한 곳이다.

```js
// esc() 이후에 적용 — 순서가 바뀌면 XSS
const linkify = (s) => s.replace(/https?:\/\/[^\s<]+/g, (u) => `<a href="${u}" target="_blank" rel="noopener">${u}</a>`);
```
- 반드시 `esc()` **뒤에** 돌린다.
- 목록 뷰 memo 셀 + 프로젝트 뷰 헤더의 상위 memo에 적용.

### mcp.js
- `weekly_review`의 `completed` 항목에 memo **첫 줄**을 포함. 주간보고 초안이 여기서 바로 나온다.

**검증**: 경과 2줄을 찍고 순서·날짜 확인, 태스크를 다시 열어 유지 확인, URL을 붙여넣고 목록에서 클릭 확인.

## 보류

- **하위 태스크 2단계 이상** — 1단계 제약은 그대로. 순환 방지가 공짜다.
- **대기 진입 시각 컬럼** — 「N일째 대기」를 마감일 초과 일수로 근사한다. 근사가 불편해지면 그때 컬럼을 판다.
- **월 단위 반복** — 기존 제약 유지.
- **`priority` / `type` 컬럼 DROP** — 코드가 안 보면 없는 것과 같다. 되돌릴 수 없는 삭제를 이득 없이 하지 않는다.
